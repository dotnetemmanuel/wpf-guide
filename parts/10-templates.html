PART 10

Templates

A ControlTemplate replaces a control's appearance while keeping its behaviour. A DataTemplate decides how a data object is drawn. Between them they are the reason WPF is still worth using.

Builds on Part 7, the control content model (content, containers and the visual tree) and Part 9, styles and triggers.

ControlTemplate

A style can only set properties a control already has. Ask for a fully rounded button and you find Button has no CornerRadius to set: the corners belong to elements drawn inside it. To change those, you replace the drawing itself. A ControlTemplate is the tree of elements that draws a control, and every control's template is replaceable.

A Button's behaviour (click detection, keyboard activation, command invocation, IsPressed) lives in ButtonBase. Its appearance is entirely in a replaceable template. Swap the template and you still have a real button.

IN PLAIN TERMS

A control is like a car: the engine, steering and brakes are its behaviour, the bodywork is its appearance. A ControlTemplate is a new body on the same chassis, so a pill-shaped button still clicks, takes keyboard focus and runs its command. Where the analogy stops: the new body shows only the settings you connect to it, so a template that ignores Background makes the button's Background do nothing.

The style below sets ordinary properties first, then replaces Template with a Border that has fully rounded corners and a ContentPresenter inside it. The triggers belong to the template, so they can change the Border directly by its name.

XAML 
<Style x:Key="PillButton" TargetType="Button">
  <Setter Property="Background"      Value="{StaticResource AccentBrush}" />
  <Setter Property="Foreground"      Value="White" />
  <Setter Property="Padding"         Value="16,7" />
  <Setter Property="BorderThickness" Value="1" />
  <Setter Property="Cursor"          Value="Hand" />

  <Setter Property="Template">
    <Setter.Value>
      <ControlTemplate TargetType="Button">
        <Border x:Name="Root"
                Background="{TemplateBinding Background}"
                BorderBrush="{TemplateBinding BorderBrush}"
                BorderThickness="{TemplateBinding BorderThickness}"
                Padding="{TemplateBinding Padding}"
                CornerRadius="999"
                SnapsToDevicePixels="True">
          <ContentPresenter x:Name="Content"
                            HorizontalAlignment="Center"
                            VerticalAlignment="Center"
                            RecognizesAccessKey="True" />
        </Border>

        <ControlTemplate.Triggers>
          <Trigger Property="IsMouseOver" Value="True">
            <Setter TargetName="Root" Property="Opacity" Value="0.9" />
          </Trigger>
          <Trigger Property="IsPressed" Value="True">
            <Setter TargetName="Content" Property="Margin" Value="0,1,0,-1" />
          </Trigger>
          <Trigger Property="IsKeyboardFocused" Value="True">
            <Setter TargetName="Root" Property="BorderBrush"
                    Value="{StaticResource FocusBrush}" />
          </Trigger>
          <Trigger Property="IsEnabled" Value="False">
            <Setter TargetName="Root" Property="Opacity" Value="0.4" />
          </Trigger>
        </ControlTemplate.Triggers>
      </ControlTemplate>
    </Setter.Value>
  </Setter>
</Style>

Three things carry the weight here. The first two refer to the templated parent, which simply means the control the template is applied to: here, the button.

  • TemplateBinding is a lightweight, one-way binding to the templated control's own property, set up when the template is applied. Use it inside templates; it is meaningfully faster than {Binding RelativeSource={RelativeSource TemplatedParent}}. It accepts a converter but does no automatic type conversion. Use the long form when you need two-way, a nested path, a type conversion without a converter, or a binding inside a Freezable such as a brush, where TemplateBinding does not work.
  • ContentPresenter is where Content lands. It automatically picks up ContentTemplate and ContentStringFormat from the templated parent. For an ItemsControl the equivalent is ItemsPresenter.
  • Setter TargetName is only legal inside a template's own triggers (ControlTemplate.Triggers, or DataTemplate.Triggers), not Style.Triggers. A style trigger cannot reach into the template's named parts.
IN PLAIN TERMS

A template is a printed form with blanks. Each TemplateBinding is a blank labelled with a property name, filled in with that button's own value. The ContentPresenter is the large box where whatever the button contains gets drawn. Anything not written as a blank is printed on the form: CornerRadius="999" is fixed, so no button using this template can change it.

The parts-and-states contract DEEPER

If you write a control that others can retemplate, your code still needs particular elements from whatever template it is given, such as the thumb of a slider. The agreement is by name. A template part is a named element, conventionally prefixed PART_, that the control's code looks for.

When you write a custom control you should publish which named parts your template is expected to contain, and look them up defensively. [TemplatePart] documents them for tools and template authors; nothing enforces it at runtime, so a template may leave a part out (Part 27 covers the whole authoring story):

C# 
[TemplatePart(Name = PartTrack,  Type = typeof(FrameworkElement))]
[TemplatePart(Name = PartThumb,  Type = typeof(Thumb))]
public class RangeSlider : Control
{
    public const string PartTrack = "PART_Track";
    public const string PartThumb = "PART_Thumb";

    private Thumb? _thumb;

    static RangeSlider()
    {
        // Tells WPF to look up the default style (and its template) in the theme dictionaries, usually Themes/Generic.xaml
        DefaultStyleKeyProperty.OverrideMetadata(
            typeof(RangeSlider), new FrameworkPropertyMetadata(typeof(RangeSlider)));
    }

    public override void OnApplyTemplate()
    {
        base.OnApplyTemplate();

        if (_thumb is not null) _thumb.DragDelta -= OnDrag;

        _thumb = GetTemplateChild(PartThumb) as Thumb;   // may legitimately be null
        if (_thumb is not null) _thumb.DragDelta += OnDrag;
    }

    private void OnDrag(object sender, DragDeltaEventArgs e) { /* … */ }
}

Unhooking before re-hooking matters: OnApplyTemplate runs again every time the template is replaced, and a theme switch does exactly that.

DataTemplate

Your view models are plain classes that know nothing about the screen. Something has to decide what an InvoiceViewModel looks like when it appears in a ContentControl or a list, and ideally the view model should not be involved in that decision.

A DataTemplate keyed by DataType rather than x:Key becomes an implicit template: any time WPF is asked to render an object of that type without an explicit template, it finds this one.

IN PLAIN TERMS

Implicit templates work like file associations in Windows. Double-click a PDF and the PDF reader opens; you never tell each file which program to use, because the association was registered once, by file type. Put an InvoiceViewModel in a ContentControl and WPF opens it with InvoiceView the same way. Where the analogy stops: with no association registered, WPF does not ask, it shows the ToString() text.

XAML 
<Application.Resources>
  <DataTemplate DataType="{x:Type vm:CustomerViewModel}">
    <views:CustomerView />
  </DataTemplate>
  <DataTemplate DataType="{x:Type vm:InvoiceViewModel}">
    <views:InvoiceView />
  </DataTemplate>
</Application.Resources>

<!-- Anywhere in the app: -->
<ContentControl Content="{Binding CurrentPage}" />

That six-line pattern is view-model-first navigation. Set CurrentPage to an InvoiceViewModel and the invoice view appears. The view's DataContext is the view model it was chosen for, so its bindings work with no further wiring, unless the view sets its own DataContext. No navigation framework, no view locator, no code. It is the single most valuable thing in WPF's design and the thing most worth building your application architecture around.

DataTemplateSelector DEEPER

For when the choice is not by type, say by a property value. A DataTemplateSelector is a class with one method that receives the item and returns the template to use:

C# 
public sealed class MessageTemplateSelector : DataTemplateSelector
{
    public DataTemplate? Compact { get; set; }
    public DataTemplate? Expanded { get; set; }

    public override DataTemplate? SelectTemplate(object? item, DependencyObject container)
        => item is MessageViewModel { IsExpanded: true } ? Expanded : Compact;
}

You give it the candidate templates as properties and set it on the list. CompactMessage and ExpandedMessage are ordinary keyed DataTemplate resources:

XAML 
<ListBox ItemsSource="{Binding Messages}">
  <ListBox.ItemTemplateSelector>
    <sel:MessageTemplateSelector
        Compact="{StaticResource CompactMessage}"
        Expanded="{StaticResource ExpandedMessage}" />
  </ListBox.ItemTemplateSelector>
</ListBox>
GOTCHA

SelectTemplate is called once when the container is created, not when your properties change. If IsExpanded flips later, nothing re-runs. For state that changes, use a single template with a DataTrigger swapping ContentTemplate, or trigger container regeneration.

Finding the default template of a built-in control

Before you write a template from scratch, start from the real one. The default template already handles states you would otherwise forget, such as keyboard focus and disabled. Three routes:

  • The WPF source at dotnet/wpf, in src/…/Themes/PresentationFramework.Aero2/Themes/Aero2.NormalColor.xaml.
  • Right-click a control in the Visual Studio designer → Edit Template → Edit a Copy, which emits the full default into your dictionary.
  • Programmatically, for the curious:
C# 
// The theme style for a type lives under the type itself as a resource key.
var style = (Style?)Application.Current.TryFindResource(typeof(Button));

var template = style?.Setters
    .OfType<Setter>()
    .FirstOrDefault(x => x.Property == Control.TemplateProperty)
    ?.Value as ControlTemplate;

if (template is not null)
{
    var settings = new XmlWriterSettings { Indent = true, IndentChars = "  " };
    using var writer = XmlWriter.Create(Console.Out, settings);
    XamlWriter.Save(template, writer);
}
RECAP
  • A ControlTemplate replaces how a control looks, while its behaviour stays in the control class.
  • Inside a template, TemplateBinding connects elements to the control's properties and ContentPresenter shows its content.
  • Triggers inside a template can change named elements with TargetName, and style triggers cannot.
  • A DataTemplate with a DataType and no key is used for every object of that type, which gives you view-model-first navigation.
  • A DataTemplateSelector runs when an item's container is created, and again when a recycled container is reused, but not when the item's properties change.
  • Start a new template from a copy of the default one.
