PART 22

Images, media and imaging

Loading images correctly

The naive <Image Source="photo.jpg" /> decodes at full resolution regardless of display size. For a 4000×3000 photo shown in a 120px thumbnail that is roughly 48 MB of pixels per image. DecodePixelWidth fixes it:

XAML 
<Image Width="120" Height="90">
  <Image.Source>
    <BitmapImage UriSource="{Binding PhotoPath}"
                 DecodePixelWidth="240"
                 CacheOption="OnLoad"
                 CreateOptions="IgnoreImageCache" />
  </Image.Source>
</Image>
SettingWhy
DecodePixelWidthDecode at this width only. Set it to roughly 2× the display size for high-DPI headroom. Set one dimension; the other follows.
CacheOption="OnLoad"Read the whole stream immediately and close the file. Without it the file stays locked and you cannot delete or overwrite it.
CreateOptions="IgnoreImageCache"Bypass WPF's URI-keyed cache. Needed when the file at a path changes and you want the new content.
C# — loading from a stream without locking the file 
public static BitmapImage LoadThumbnail(string path, int width)
{
    using var stream = File.OpenRead(path);
    var bmp = new BitmapImage();
    bmp.BeginInit();
    bmp.CacheOption = BitmapCacheOption.OnLoad;
    bmp.DecodePixelWidth = width;
    bmp.StreamSource = stream;
    bmp.EndInit();
    bmp.Freeze();        // safe to hand to the UI thread from a background thread
    return bmp;
}

Because the result is frozen, this whole method can run on a thread-pool thread. That is how you build a responsive photo grid.

Encoding, screenshots and pixel work

C# — render any element to a PNG 
public static void SaveElementAsPng(FrameworkElement element, string path, double dpi = 96)
{
    double scale = dpi / 96.0;
    var rtb = new RenderTargetBitmap(
        (int)Math.Ceiling(element.ActualWidth  * scale),
        (int)Math.Ceiling(element.ActualHeight * scale),
        dpi, dpi, PixelFormats.Pbgra32);

    // Render through a VisualBrush so element transforms and margins are respected.
    var visual = new DrawingVisual();
    using (var dc = visual.RenderOpen())
    {
        dc.DrawRectangle(new VisualBrush(element), null,
            new Rect(new Point(), new Size(element.ActualWidth, element.ActualHeight)));
    }
    rtb.Render(visual);

    var encoder = new PngBitmapEncoder();
    encoder.Frames.Add(BitmapFrame.Create(rtb));
    using var fs = File.Create(path);
    encoder.Save(fs);
}

Encoders available out of the box: PngBitmapEncoder, JpegBitmapEncoder (with QualityLevel), BmpBitmapEncoder, GifBitmapEncoder, TiffBitmapEncoder, WmpBitmapEncoder. Decoders mirror them, and BitmapDecoder.Create sniffs the format.

C# — WriteableBitmap for direct pixel access 
var wb = new WriteableBitmap(width, height, 96, 96, PixelFormats.Bgra32, null);

wb.Lock();
try
{
    unsafe
    {
        var buffer = (byte*)wb.BackBuffer;
        int stride = wb.BackBufferStride;
        for (int y = 0; y < height; y++)
        for (int x = 0; x < width; x++)
        {
            int i = y * stride + x * 4;
            buffer[i + 0] = blue;
            buffer[i + 1] = green;
            buffer[i + 2] = red;
            buffer[i + 3] = 255;          // alpha; format is premultiplied for Pbgra32
        }
    }
    wb.AddDirtyRect(new Int32Rect(0, 0, width, height));
}
finally { wb.Unlock(); }

Requires <AllowUnsafeBlocks>true</AllowUnsafeBlocks>. The safe alternative is wb.WritePixels(rect, array, stride, offset), which copies — fine for occasional updates, too slow for per-frame work.

Reading metadata

C# 
using var fs = File.OpenRead(path);
var decoder = BitmapDecoder.Create(fs, BitmapCreateOptions.DelayCreation,
                                       BitmapCacheOption.OnDemand);
var frame = decoder.Frames[0];

if (frame.Metadata is BitmapMetadata meta)
{
    string? camera = meta.CameraModel;
    DateTime? taken = DateTime.TryParse(meta.DateTaken, out var d) ? d : null;
    var tags = meta.Keywords;
    // Raw EXIF by path:
    object? iso = meta.GetQuery("/app1/ifd/exif/subifd:{uint=34855}");
}

Audio and video

XAML 
<MediaElement x:Name="Player"
              Source="{Binding VideoPath}"
              LoadedBehavior="Manual"
              UnloadedBehavior="Stop"
              ScrubbingEnabled="True"
              Stretch="Uniform"
              MediaOpened="OnOpened"
              MediaEnded="OnEnded"
              MediaFailed="OnFailed" />
C# 
Player.Play();
Player.Pause();
Player.Position = TimeSpan.FromSeconds(30);
double seconds = Player.NaturalDuration.HasTimeSpan
    ? Player.NaturalDuration.TimeSpan.TotalSeconds : 0;
GOTCHA

LoadedBehavior must be Manual before Play(), Pause() or Position do anything — the default Play puts the element in clock-driven mode and ignores your calls. MediaElement also wraps Windows Media Player codecs, so format support depends on the machine and there is no error until MediaFailed fires. For anything serious, host LibVLCSharp.WPF or a WebView2 instead.

For short UI sounds, skip MediaElement entirely:

C# 
SystemSounds.Exclamation.Play();                      // system sounds
new SoundPlayer(@"Assets\ding.wav").Play();           // WAV only, fire and forget
