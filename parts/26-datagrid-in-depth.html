DataGrid in depth

The heaviest control in the box and the one most business applications are built on. Worth knowing properly.

Columns

XAML 
<DataGrid ItemsSource="{Binding Rows}"
          AutoGenerateColumns="False"
          CanUserAddRows="False"
          CanUserDeleteRows="False"
          CanUserReorderColumns="True"
          SelectionMode="Extended"
          SelectionUnit="FullRow"
          GridLinesVisibility="Horizontal"
          HeadersVisibility="Column"
          EnableRowVirtualization="True"
          EnableColumnVirtualization="False"
          VirtualizingPanel.VirtualizationMode="Recycling"
          RowHeight="26"
          FrozenColumnCount="1">

  <DataGrid.Columns>
    <DataGridTextColumn Header="Title" Width="2*"
                        Binding="{Binding Title}"
                        SortMemberPath="Title" />

    <DataGridTextColumn Header="Due" Width="110"
                        Binding="{Binding DueDate, StringFormat=yyyy-MM-dd}">
      <DataGridTextColumn.ElementStyle>
        <Style TargetType="TextBlock">
          <Setter Property="HorizontalAlignment" Value="Right" />
          <Style.Triggers>
            <DataTrigger Binding="{Binding IsOverdue}" Value="True">
              <Setter Property="Foreground" Value="{DynamicResource DangerBrush}" />
            </DataTrigger>
          </Style.Triggers>
        </Style>
      </DataGridTextColumn.ElementStyle>
    </DataGridTextColumn>

    <DataGridCheckBoxColumn Header="Done" Width="60"
                            Binding="{Binding IsDone, UpdateSourceTrigger=PropertyChanged}" />

    <DataGridComboBoxColumn Header="Assignee" Width="150"
        SelectedValueBinding="{Binding AssigneeId}"
        SelectedValuePath="Id"
        DisplayMemberPath="Name">
      <DataGridComboBoxColumn.ElementStyle>
        <Style TargetType="ComboBox">
          <Setter Property="ItemsSource"
                  Value="{Binding DataContext.People,
                                  RelativeSource={RelativeSource AncestorType=DataGrid}}" />
        </Style>
      </DataGridComboBoxColumn.ElementStyle>
      <DataGridComboBoxColumn.EditingElementStyle>
        <Style TargetType="ComboBox">
          <Setter Property="ItemsSource"
                  Value="{Binding DataContext.People,
                                  RelativeSource={RelativeSource AncestorType=DataGrid}}" />
        </Style>
      </DataGridComboBoxColumn.EditingElementStyle>
    </DataGridComboBoxColumn>

    <DataGridTemplateColumn Header="" Width="40">
      <DataGridTemplateColumn.CellTemplate>
        <DataTemplate>
          <Button Content="×" Width="20" Height="20"
                  Command="{Binding DataContext.DeleteCommand,
                                    RelativeSource={RelativeSource AncestorType=DataGrid}}"
                  CommandParameter="{Binding}" />
        </DataTemplate>
      </DataGridTemplateColumn.CellTemplate>
    </DataGridTemplateColumn>
  </DataGrid.Columns>
</DataGrid>
GOTCHA

DataGridComboBoxColumn is the single most frustrating class in WPF. It is not part of the visual tree in the normal way, so {Binding} inside it cannot see the DataGrid's DataContext — which is why the ItemsSource has to be pushed in through both ElementStyle and EditingElementStyle. The alternative that many teams settle on is a DataGridTemplateColumn containing a plain ComboBox, which behaves like everything else.

Selection from a view model

SelectedItems is not a dependency property, so it cannot be bound. Three options:

  1. Put an IsSelected property on the row view model and bind it in RowStyle. Cleanest, and it survives virtualisation.
  2. A behaviour that syncs SelectedItems to a collection.
  3. SelectionChanged in code-behind pushing into the view model. Works, but it's the one that gets copied everywhere.
XAML — option 1 
<DataGrid.RowStyle>
  <Style TargetType="DataGridRow">
    <Setter Property="IsSelected" Value="{Binding IsSelected, Mode=TwoWay}" />
    <Style.Triggers>
      <DataTrigger Binding="{Binding HasConflict}" Value="True">
        <Setter Property="Background" Value="{DynamicResource WarnSurfaceBrush}" />
      </DataTrigger>
    </Style.Triggers>
  </Style>
</DataGrid.RowStyle>

Editing, commit and validation

The DataGrid has a two-level commit model: cell then row. IEditableObject on your row type gives you transactional row editing for free:

C# 
public partial class TaskRowViewModel : ObservableValidator, IEditableObject
{
    private TaskSnapshot? _backup;

    public void BeginEdit()   => _backup ??= Snapshot();
    public void CancelEdit()  { if (_backup is { } b) { Restore(b); _backup = null; } }
    public void EndEdit()     => _backup = null;
}

Escape once cancels the cell; Escape twice cancels the row and calls CancelEdit. To validate the whole row, use a DataGrid.RowValidationRules entry with ValidationStep="UpdatedValue":

XAML 
<DataGrid.RowValidationRules>
  <rules:TaskRowRule ValidationStep="UpdatedValue" />
</DataGrid.RowValidationRules>

<DataGrid.RowValidationErrorTemplate>
  <ControlTemplate>
    <Grid Margin="0,-2,0,-2" ToolTip="{Binding RelativeSource={RelativeSource
              AncestorType=DataGridRow}, Path=(Validation.Errors)[0].ErrorContent}">
      <Ellipse Width="12" Height="12" Fill="{DynamicResource DangerBrush}" />
      <TextBlock Text="!" Foreground="White" FontWeight="Bold" FontSize="9"
                 HorizontalAlignment="Center" VerticalAlignment="Center" />
    </Grid>
  </ControlTemplate>
</DataGrid.RowValidationErrorTemplate>

Performance rules for large grids

  • Set an explicit RowHeight. Without it, the grid measures every row to find the tallest, defeating virtualisation on first layout.
  • Avoid Width="Auto" and SizeToCells columns. They force every row to be measured. Use * and fixed widths.
  • Leave EnableColumnVirtualization="False" unless you genuinely have 50+ columns; it costs more than it saves below that.
  • Keep CellStyle and templates shallow. Every extra Border is multiplied by rows × columns.
  • Do not bind ItemsSource to a LINQ query. It re-enumerates. Materialise to a list first.
  • Turn off CanUserSortColumns if you sort server-side, and handle Sorting yourself with e.Handled = true.
C# — server-side sorting 
private async void OnSorting(object sender, DataGridSortingEventArgs e)
{
    e.Handled = true;
    var column = e.Column;

    column.SortDirection = column.SortDirection == ListSortDirection.Ascending
        ? ListSortDirection.Descending
        : ListSortDirection.Ascending;

    await _viewModel.SortAsync(column.SortMemberPath, column.SortDirection.Value);
}
