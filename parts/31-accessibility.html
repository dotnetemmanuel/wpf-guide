PART 31

Accessibility

In much of Europe the EN 301 549 standard makes this a procurement requirement rather than a nice-to-have. WPF's automation support is good; the defaults are not.

The five things that cover most of it

XAML 
<!-- 1. Name every control that has no visible text label -->
<Button Command="{Binding DeleteCommand}"
        AutomationProperties.Name="Delete task"
        ToolTip="Delete task">
  <Path Data="{StaticResource TrashGeometry}" />
</Button>

<!-- 2. Associate labels with fields -->
<Label Content="_Due date" Target="{Binding ElementName=DueBox}" />
<DatePicker x:Name="DueBox"
            AutomationProperties.LabeledBy="{Binding ElementName=DueLabel}" />

<!-- 3. Hide decorative visuals from the automation tree -->
<Path Data="{StaticResource DividerGeometry}"
      AutomationProperties.AccessibilityView="Raw" />

<!-- 4. Announce live changes -->
<TextBlock Text="{Binding StatusMessage}"
           AutomationProperties.LiveSetting="Polite" />

<!-- 5. Give the user a keyboard path to everything -->
<Button Content="_Save" IsDefault="True" />

Testing it

  • Accessibility Insights for Windows — free from Microsoft. Live inspection of the automation tree plus automated checks. Run it before you ship.
  • Narrator (Win+Ctrl+Enter) or NVDA — actually listen to your screen. Ten minutes tells you more than any checklist.
  • Unplug the mouse and complete your main workflow. The fastest test there is.
  • High contrast — Win+Alt+PrintScreen. Anything using a hard-coded colour disappears.

High contrast

XAML 
<Style TargetType="Border" x:Key="Card">
  <Setter Property="Background" Value="{DynamicResource SurfaceBrush}" />
  <Setter Property="BorderBrush" Value="{DynamicResource BorderBrush}" />
  <Style.Triggers>
    <DataTrigger Binding="{Binding Source={x:Static SystemParameters.HighContrast}}"
                 Value="True">
      <Setter Property="Background"
              Value="{DynamicResource {x:Static SystemColors.WindowBrushKey}}" />
      <Setter Property="BorderBrush"
              Value="{DynamicResource {x:Static SystemColors.WindowTextBrushKey}}" />
      <Setter Property="BorderThickness" Value="1" />
    </DataTrigger>
  </Style.Triggers>
</Style>

The general rule: never convey information by colour alone, and in high contrast mode fall back to SystemColors keys rather than your palette.

Custom controls need a custom peer

If you write a lookless control, screen readers see a generic element unless you supply an AutomationPeer:

C# 
public class RatingBar : Control
{
    protected override AutomationPeer OnCreateAutomationPeer() => new RatingBarPeer(this);

    internal void RaiseValueChanged(int oldValue, int newValue)
    {
        if (UIElementAutomationPeer.FromElement(this) is RatingBarPeer peer)
            peer.RaisePropertyChangedEvent(
                RangeValuePatternIdentifiers.ValueProperty,
                (double)oldValue, (double)newValue);
    }
}

public sealed class RatingBarPeer(RatingBar owner)
    : FrameworkElementAutomationPeer(owner), IRangeValueProvider
{
    protected override AutomationControlType GetAutomationControlType()
        => AutomationControlType.Slider;

    protected override string GetClassNameCore() => nameof(RatingBar);

    public override object? GetPattern(PatternInterface pattern)
        => pattern == PatternInterface.RangeValue ? this : base.GetPattern(pattern);

    // IRangeValueProvider
    public double Value => ((RatingBar)Owner).Value;
    public double Minimum => 0;
    public double Maximum => ((RatingBar)Owner).Maximum;
    public double SmallChange => 1;
    public double LargeChange => 1;
    public bool IsReadOnly => !Owner.IsEnabled;

    public void SetValue(double value) => ((RatingBar)Owner).Value = (int)Math.Round(value);
}

Implementing the right pattern — IInvokeProvider, IToggleProvider, ISelectionProvider, IRangeValueProvider — is also what makes the control drivable by UI automation tests (Part 20), so the accessibility work pays for itself twice.

SINCE .NET 9 / .NET 10

Both releases contain substantial UI Automation fixes, including better NVDA compatibility and added RecognizesAccessKey on controls that were missing it in the Fluent theme. .NET 10 also improved automation performance by cutting allocations in the automation layer. If accessibility is contractual for you, target .NET 10.
