PART 33

Data access and services

EF Core in a desktop app

Desktop is not web: there is no request boundary, so DbContext lifetime has to be decided by you. The rule that works is one context per unit of work, never a singleton.

C# 
// Registration
builder.Services.AddDbContextFactory<TasksDbContext>(options =>
    options.UseSqlite($"Data Source={AppPaths.Database}"));

// Usage — a short-lived context per operation
public sealed class TaskRepository(IDbContextFactory<TasksDbContext> factory) : ITaskRepository
{
    public async Task<IReadOnlyList<TaskDto>> GetAllAsync(CancellationToken ct)
    {
        await using var db = await factory.CreateDbContextAsync(ct);
        return await db.Tasks
            .AsNoTracking()
            .OrderBy(t => t.DueDate)
            .Select(t => new TaskDto(t.Id, t.Title, t.IsDone, t.DueDate))
            .ToListAsync(ct);
    }

    public async Task SaveAsync(TaskDto dto, CancellationToken ct)
    {
        await using var db = await factory.CreateDbContextAsync(ct);
        var entity = await db.Tasks.FindAsync([dto.Id], ct);
        if (entity is null) { db.Tasks.Add(TaskEntity.From(dto)); }
        else { entity.Apply(dto); }
        await db.SaveChangesAsync(ct);
    }
}
GOTCHA

Never bind the UI directly to EF entities. Tracked entities hold a reference to their context; a bound DbSet keeps the context alive for the lifetime of the window, lazy loading fires on the UI thread during layout, and a single SaveChanges can cascade changes you never intended. Project to DTOs or view models at the repository boundary. AsNoTracking() on every read query is the habit to build.

Migrations at startup

C# 
public sealed class DatabaseMigrator(
    IDbContextFactory<TasksDbContext> factory,
    ILogger<DatabaseMigrator> log) : IHostedService
{
    public async Task StartAsync(CancellationToken ct)
    {
        await using var db = await factory.CreateDbContextAsync(ct);
        var pending = (await db.Database.GetPendingMigrationsAsync(ct)).ToList();
        if (pending.Count == 0) return;

        log.LogInformation("Applying {Count} migrations: {Names}", pending.Count, pending);
        BackupDatabase();
        await db.Database.MigrateAsync(ct);
    }

    public Task StopAsync(CancellationToken ct) => Task.CompletedTask;
}

Register it with AddHostedService before anything that touches data. Because _host.StartAsync() is awaited in OnStartup, migration completes before the first window shows. Back up first — an interrupted migration on a user's local SQLite file is unrecoverable otherwise.

Calling HTTP APIs

C# 
builder.Services
    .AddHttpClient<ITaskApi, TaskApi>((sp, http) =>
    {
        var o = sp.GetRequiredService<IOptions<ApiOptions>>().Value;
        http.BaseAddress = new Uri(o.BaseUrl);
        http.Timeout = TimeSpan.FromSeconds(30);
        http.DefaultRequestHeaders.UserAgent.ParseAdd($"Tasks/{BuildInfo.Version}");
    })
    .AddStandardResilienceHandler();      // Microsoft.Extensions.Http.Resilience
C# 
public sealed class TaskApi(HttpClient http) : ITaskApi
{
    private static readonly JsonSerializerOptions Json =
        new(JsonSerializerDefaults.Web);

    public async Task<IReadOnlyList<TaskDto>> GetChangesAsync(
        DateTimeOffset since, CancellationToken ct)
    {
        using var response = await http.GetAsync(
            $"tasks?since={since:O}", HttpCompletionOption.ResponseHeadersRead, ct);

        response.EnsureSuccessStatusCode();

        await using var stream = await response.Content.ReadAsStreamAsync(ct);
        return await JsonSerializer.DeserializeAsync<List<TaskDto>>(stream, Json, ct) ?? [];
    }
}

AddHttpClient<TInterface, TImplementation> registers the typed client with a managed HttpMessageHandler pool, which avoids both socket exhaustion and the stale-DNS problem you get from a static HttpClient. Never construct HttpClient with new in application code.

An offline-capable read path

The pattern most desktop line-of-business apps converge on: read local, sync in the background, surface staleness.

C# 
public sealed class TaskService(
    ITaskRepository local, ITaskApi remote, IClock clock, ILogger<TaskService> log)
{
    public async Task<LoadResult<TaskDto>> LoadAsync(CancellationToken ct)
    {
        // 1. Always return local data immediately — the UI never waits on the network.
        var cached = await local.GetAllAsync(ct);

        // 2. Refresh in the background and report the outcome, don't throw.
        try
        {
            var since = await local.GetLastSyncAsync(ct);
            var changes = await remote.GetChangesAsync(since, ct);
            await local.MergeAsync(changes, clock.UtcNow, ct);
            return new LoadResult<TaskDto>(await local.GetAllAsync(ct), IsStale: false, null);
        }
        catch (Exception ex) when (ex is HttpRequestException or TaskCanceledException)
        {
            log.LogWarning(ex, "Working offline");
            return new LoadResult<TaskDto>(cached, IsStale: true, "Showing saved data");
        }
    }
}

public sealed record LoadResult<T>(
    IReadOnlyList<T> Items, bool IsStale, string? Message);

Bind IsStale to an info bar. Users tolerate stale data; they do not tolerate a spinner that never resolves or an exception dialog because the VPN dropped.

Where files go

KindFolder
Per-user data, databases, cachesSpecialFolder.LocalApplicationData — %LOCALAPPDATA%
Per-user settings that should roamSpecialFolder.ApplicationData — %APPDATA%
Machine-wide read-only configSpecialFolder.CommonApplicationData — %PROGRAMDATA%
User documents the user managesSpecialFolder.MyDocuments, in a named subfolder
NeverThe install directory. It is read-only for standard users and you will get access-denied reports.
