Windows integration and custom chrome

Taskbar

XAML 
<Window.TaskbarItemInfo>
  <TaskbarItemInfo ProgressState="{Binding TaskbarState}"
                   ProgressValue="{Binding Progress}"
                   Overlay="{Binding OverlayIcon}"
                   Description="{Binding Title}">
    <TaskbarItemInfo.ThumbButtonInfos>
      <ThumbButtonInfoCollection>
        <ThumbButtonInfo Description="Sync now"
                         ImageSource="/Assets/sync.png"
                         Command="{Binding SyncCommand}" />
      </ThumbButtonInfoCollection>
    </TaskbarItemInfo.ThumbButtonInfos>
  </TaskbarItemInfo>
</Window.TaskbarItemInfo>

ProgressState takes None, Normal, Paused, Error or Indeterminate. Wiring it to a long-running import is a two-minute change that makes an app feel considerably more native.

Jump lists

C# 
public static void PublishRecent(IEnumerable<string> paths)
{
    var list = new JumpList { ShowRecentCategory = false, ShowFrequentCategory = false };

    foreach (string path in paths.Take(10))
    {
        list.JumpItems.Add(new JumpTask
        {
            Title = Path.GetFileNameWithoutExtension(path),
            Description = path,
            ApplicationPath = Environment.ProcessPath,
            Arguments = $"\"{path}\"",
            IconResourcePath = Environment.ProcessPath,
            CustomCategory = "Recent projects",
        });
    }

    JumpList.SetJumpList(Application.Current, list);
    list.Apply();
}

Tray icon and notifications

WPF has no tray icon. Two options: reference WinForms for NotifyIcon, or use H.NotifyIcon.Wpf, which is XAML-native and better behaved.

XAML — H.NotifyIcon 
xmlns:tb="clr-namespace:H.NotifyIcon;assembly=H.NotifyIcon.Wpf"

<tb:TaskbarIcon IconSource="/Assets/tray.ico"
                ToolTipText="Tasks"
                LeftClickCommand="{Binding ShowWindowCommand}">
  <tb:TaskbarIcon.ContextMenu>
    <ContextMenu>
      <MenuItem Header="Sync now" Command="{Binding SyncCommand}" />
      <Separator />
      <MenuItem Header="Exit"     Command="{Binding ExitCommand}" />
    </ContextMenu>
  </tb:TaskbarIcon.ContextMenu>
</tb:TaskbarIcon>

For real Windows toast notifications, target a Windows SDK TFM and use Microsoft.Toolkit.Uwp.Notifications / CommunityToolkit.WinUI.Notifications. Toasts require a registered AUMID, which in practice means either an MSIX package or a shortcut in the Start menu carrying the ID.

Custom window chrome

The supported way to draw your own title bar while keeping snapping, resizing, Aero shake and maximise behaviour:

XAML 
<Window x:Class="Tasks.Shell"
        WindowStyle="SingleBorderWindow"
        Background="{DynamicResource SurfaceBrush}">

  <WindowChrome.WindowChrome>
    <WindowChrome CaptionHeight="36"
                  ResizeBorderThickness="6"
                  CornerRadius="0"
                  GlassFrameThickness="0,0,0,1"
                  UseAeroCaptionButtons="False" />
  </WindowChrome.WindowChrome>

  <DockPanel>
    <Grid DockPanel.Dock="Top" Height="36" Background="{DynamicResource TitleBarBrush}">
      <Grid.ColumnDefinitions>
        <ColumnDefinition Width="*" />
        <ColumnDefinition Width="Auto" />
      </Grid.ColumnDefinitions>

      <TextBlock Text="{Binding Title}" Margin="12,0,0,0"
                 VerticalAlignment="Center" FontSize="12" />

      <!-- Buttons must opt out of the caption area or they aren't clickable -->
      <StackPanel Grid.Column="1" Orientation="Horizontal"
                  WindowChrome.IsHitTestVisibleInChrome="True">
        <Button Style="{StaticResource CaptionButton}" Content="─"
                Click="OnMinimise" />
        <Button Style="{StaticResource CaptionButton}" Content="◻"
                Click="OnMaximise" />
        <Button Style="{StaticResource CloseButton}"   Content="✕"
                Click="OnClose" />
      </StackPanel>
    </Grid>

    <ContentControl Content="{Binding Current}" />
  </DockPanel>
</Window>
C# 
private void OnMinimise(object s, RoutedEventArgs e) => WindowState = WindowState.Minimized;
private void OnClose(object s, RoutedEventArgs e) => Close();
private void OnMaximise(object s, RoutedEventArgs e) =>
    WindowState = WindowState == WindowState.Maximized
        ? WindowState.Normal : WindowState.Maximized;
GOTCHA

A maximised WindowChrome window overflows the screen by the resize-border thickness, hiding the top few pixels of your title bar. The standard fix is to add a margin equal to SystemParameters.WindowResizeBorderThickness when WindowState == Maximized, via a trigger on the root element. Every custom-chrome implementation has this workaround in it somewhere.

Mica and dark title bars

C# 
internal static class DwmWindow
{
    private const int UseImmersiveDarkMode = 20;
    private const int SystemBackdropType   = 38;

    [DllImport("dwmapi.dll")]
    private static extern int DwmSetWindowAttribute(
        IntPtr hwnd, int attribute, ref int value, int size);

    public static void ApplyDark(Window window, bool dark)
    {
        IntPtr hwnd = new WindowInteropHelper(window).EnsureHandle();
        int value = dark ? 1 : 0;
        DwmSetWindowAttribute(hwnd, UseImmersiveDarkMode, ref value, sizeof(int));
    }

    /// <summary>2 = Mica, 3 = Acrylic, 4 = Mica Alt. Windows 11 22H2+.</summary>
    public static void ApplyBackdrop(Window window, int type)
    {
        IntPtr hwnd = new WindowInteropHelper(window).EnsureHandle();
        DwmSetWindowAttribute(hwnd, SystemBackdropType, ref type, sizeof(int));
    }
}

For Mica to show through, the window background must be transparent and WindowChrome.GlassFrameThickness set to -1. It fails silently on Windows 10, so feature-detect on Environment.OSVersion.Version.Build >= 22000.

SINCE .NET 9

The built-in Fluent theme (ThemeMode, Part 8) handles the dark title bar and backdrop for you on supported Windows versions, so check whether you need this P/Invoke at all before writing it. .NET 11 previews fix Fluent backdrop and background defects specifically on Windows 10 — another reason to feature-detect rather than assume.

Persisting window placement

C# 
public sealed record WindowPlacement(
    double Left, double Top, double Width, double Height, bool Maximised);

public static void Restore(Window window, WindowPlacement p)
{
    // Reject placements entirely outside the current monitor layout.
    var virt = new Rect(SystemParameters.VirtualScreenLeft,
                        SystemParameters.VirtualScreenTop,
                        SystemParameters.VirtualScreenWidth,
                        SystemParameters.VirtualScreenHeight);

    var target = new Rect(p.Left, p.Top, p.Width, p.Height);
    if (!virt.IntersectsWith(target))
    {
        window.WindowStartupLocation = WindowStartupLocation.CenterScreen;
        return;
    }

    window.WindowStartupLocation = WindowStartupLocation.Manual;
    window.Left = p.Left; window.Top = p.Top;
    window.Width = p.Width; window.Height = p.Height;
    if (p.Maximised) window.WindowState = WindowState.Maximized;
}

The intersection check is the part people skip, and it's why apps occasionally open on a monitor that is no longer plugged in.
