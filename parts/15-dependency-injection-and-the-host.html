PART 15

Dependency injection and the host

WPF predates Microsoft.Extensions.* by a decade, so nothing is wired up for you. Fifty lines gets you the same composition root you'd have in an ASP.NET Core app.

The wiring

App.xaml.cs 
public partial class App : Application
{
    private readonly IHost _host;

    public App()
    {
        var builder = Host.CreateApplicationBuilder();

        builder.Configuration
            .AddJsonFile("appsettings.json", optional: false)
            .AddJsonFile($"appsettings.{builder.Environment.EnvironmentName}.json", optional: true)
            .AddEnvironmentVariables("TASKS_")
            .AddUserSecrets<App>(optional: true);

        builder.Logging.ClearProviders();
        builder.Services.AddSerilog((_, cfg) => cfg
            .ReadFrom.Configuration(builder.Configuration)
            .WriteTo.File(
                Path.Combine(Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData),
                             "Tasks", "logs", "log-.txt"),
                rollingInterval: RollingInterval.Day));

        builder.Services.Configure<ApiOptions>(builder.Configuration.GetSection("Api"));

        // Infrastructure
        builder.Services.AddSingleton<IClock, SystemClock>();
        builder.Services.AddSingleton<ITaskRepository, SqliteTaskRepository>();
        builder.Services.AddHttpClient<ITaskApi, TaskApi>((sp, http) =>
        {
            var o = sp.GetRequiredService<IOptions<ApiOptions>>().Value;
            http.BaseAddress = new Uri(o.BaseUrl);
        });

        // UI services
        builder.Services.AddSingleton<IDialogService, DialogService>();
        builder.Services.AddSingleton<INavigationService, NavigationService>();

        // Windows are singletons, page/dialog view models are transient
        builder.Services.AddSingleton<MainWindow>();
        builder.Services.AddSingleton<ShellViewModel>();
        builder.Services.AddTransient<TaskListViewModel>();
        builder.Services.AddTransient<TaskEditorViewModel>();

        _host = builder.Build();
    }

    protected override async void OnStartup(StartupEventArgs e)
    {
        try
        {
            base.OnStartup(e);
            await _host.StartAsync();

            var window = _host.Services.GetRequiredService<MainWindow>();
            window.DataContext = _host.Services.GetRequiredService<ShellViewModel>();
            window.Show();
        }
        catch (Exception ex)
        {
            MessageBox.Show(ex.ToString(), "Startup failed");
            Shutdown(1);
        }
    }

    protected override async void OnExit(ExitEventArgs e)
    {
        using (_host) await _host.StopAsync(TimeSpan.FromSeconds(5));
        base.OnExit(e);
    }
}

Delete StartupUri from App.xaml or the framework will construct a second, unwired window behind the one you showed.

Lifetimes, translated to desktop

LifetimeDesktop meaning
SingletonLives as long as the process. Repositories, the shell view model, settings, the main window.
TransientNew instance per resolve. Dialog view models, page view models, anything holding per-screen state.
ScopedNo ambient scope exists in a desktop app. Create one explicitly per window or per unit of work — this is exactly how you get a per-dialog DbContext.
C# 
// A scope per editor window, disposed when the window closes.
public async Task<bool> EditAsync(int taskId)
{
    using var scope = _services.CreateScope();
    var vm = scope.ServiceProvider.GetRequiredService<TaskEditorViewModel>();
    await vm.LoadAsync(taskId);

    var window = new TaskEditorWindow { DataContext = vm, Owner = _shell };
    return window.ShowDialog() == true;
}
GOTCHA

Never inject IServiceProvider into a view model so it can resolve things later. That is the service locator anti-pattern and it hides your dependency graph. Inject a typed factory instead: Func<TaskEditorViewModel> works out of the box with Microsoft.Extensions.DependencyInjection only if you register it; otherwise define a small ITaskEditorFactory. The one place a container reference is legitimate is your navigation service, which is by definition a locator.

Background work with the host

Because you started a real host, IHostedService works. This is a clean home for sync loops, file watchers and cache warmers:

C# 
public sealed class SyncService : BackgroundService
{
    private readonly ITaskApi _api;
    private readonly ITaskRepository _repo;
    private readonly ILogger<SyncService> _log;

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        using var timer = new PeriodicTimer(TimeSpan.FromMinutes(5));
        while (await timer.WaitForNextTickAsync(stoppingToken))
        {
            try
            {
                var remote = await _api.GetChangesAsync(stoppingToken);
                await _repo.MergeAsync(remote, stoppingToken);
                WeakReferenceMessenger.Default.Send(new SyncCompleted(remote.Count));
            }
            catch (Exception ex) when (ex is not OperationCanceledException)
            {
                _log.LogWarning(ex, "Sync failed; will retry");
            }
        }
    }
}

Register with builder.Services.AddHostedService<SyncService>(). It starts with _host.StartAsync() and stops cleanly on exit. Note that it runs on a thread-pool thread, so anything touching bound collections needs the marshalling from Part 12.
