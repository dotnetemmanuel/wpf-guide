PART 29

Printing and reporting

Printing reuses what you already have: the same elements and documents you show on screen can go to paper. What changes is the page. It has a fixed size, edges the printer cannot reach, and room for only so much content.

Builds on Part 4, layout, Part 18, graphics and animation and Part 21, text, typography and documents.

Printing a visual

The simplest request is "print this chart": take something already on screen and put it on one sheet of paper. Four printing terms come up straight away. PrintDialog is the standard Windows print dialog. A print queue (PrintQueue) represents one printer. A print ticket (PrintTicket) holds the settings for a job, such as paper size, orientation and copies. The imageable area is the part of the sheet the printer can physically put ink on, inside its unprintable margins.

PrintVisual prints an element exactly as it is currently laid out. So the method below shows the dialog, reads the imageable area from the chosen printer, scales the element to fit it, runs layout again at page size with the element placed at the start of the imageable area, prints, and then restores the original transform. Notice that it borrows the live on-screen element for the duration.

C# 
public static void PrintElement(FrameworkElement element, string description)
{
    var dialog = new PrintDialog();
    if (dialog.ShowDialog() != true) return;

    // Fit the element to the printable area before printing.
    var capabilities = dialog.PrintQueue.GetPrintCapabilities(dialog.PrintTicket);
    var area = new Size(capabilities.PageImageableArea!.ExtentWidth,
                        capabilities.PageImageableArea.ExtentHeight);

    double scale = Math.Min(area.Width  / element.ActualWidth,
                            area.Height / element.ActualHeight);

    var original = element.LayoutTransform;
    element.LayoutTransform = new ScaleTransform(scale, scale);
    element.Measure(area);
    element.Arrange(new Rect(
        new Point(capabilities.PageImageableArea.OriginWidth,
                  capabilities.PageImageableArea.OriginHeight), area));

    dialog.PrintVisual(element, description);

    element.LayoutTransform = original;
    element.Measure(new Size(element.ActualWidth, element.ActualHeight));
}

Good enough for "print this chart". Not good enough for anything multi-page: a visual is one picture, so content taller than the page is only ever resized to fit, never continued on a second sheet.

Paginated printing with a FlowDocument

A report of 300 tasks has to break across pages, with text flowing from one page to the next. That is pagination, and the FlowDocument from Part 21 already knows how to do it.

IN PLAIN TERMS

A paginator (DocumentPaginator) is like a typesetter you can ask for "page 5". It works out page breaks as it goes and hands pages over one at a time. The printing system asks for pages in turn, so nobody has to lay out the whole document in advance.

A FlowDocument reflows to whatever page size it is given, so the method sets that size before asking for its paginator: the printable width and height, a PagePadding of 48 (half an inch, since WPF units are 1/96 inch), and a column width equal to the page width. Without that last setting, a printed FlowDocument lays its text out in several narrow newspaper-style columns.

C# 
public static void PrintDocument(FlowDocument doc, string description)
{
    var dialog = new PrintDialog();
    if (dialog.ShowDialog() != true) return;

    // The document must be sized to the page before pagination.
    doc.PageHeight  = dialog.PrintableAreaHeight;
    doc.PageWidth   = dialog.PrintableAreaWidth;
    doc.PagePadding = new Thickness(48);
    doc.ColumnGap   = 0;
    doc.ColumnWidth = dialog.PrintableAreaWidth;   // single column

    IDocumentPaginatorSource source = doc;
    dialog.PrintDocument(source.DocumentPaginator, description);
}

Headers, footers and page numbers

A printed report without page numbers turns into a loose pile of paper the moment someone drops it. WPF gives you no page furniture, meaning headers, footers and page numbers. You add it by wrapping the paginator:

IN PLAIN TERMS

The wrapper lays a clear sheet over each page as it comes out of the typesetter. The page underneath is untouched; the title and "Page 3 of 12" are drawn on the clear sheet. For everything else, such as how many pages there are or how big they are, the wrapper simply asks the original paginator.

In GetPage, the wrapper fetches the original page, puts its visual into a ContainerVisual, and adds a DrawingVisual on top with the title near the top-left margin and the page number at the bottom right. FormattedText needs the display scale (PixelsPerDip) to measure text correctly. The remaining members pass straight through to the inner paginator.

C# 
public sealed class HeaderFooterPaginator(
    DocumentPaginator inner, string title, Thickness margin) : DocumentPaginator
{
    public override DocumentPage GetPage(int pageNumber)
    {
        DocumentPage page = inner.GetPage(pageNumber);

        var container = new ContainerVisual();
        container.Children.Add(page.Visual);

        var chrome = new DrawingVisual();
        using (DrawingContext dc = chrome.RenderOpen())
        {
            double dpi = VisualTreeHelper.GetDpi(chrome).PixelsPerDip;
            var face = new Typeface("Segoe UI");

            var header = new FormattedText(title, CultureInfo.CurrentUICulture,
                FlowDirection.LeftToRight, face, 9, Brushes.Gray, dpi);
            dc.DrawText(header, new Point(margin.Left, margin.Top / 2));

            var footer = new FormattedText(
                $"Page {pageNumber + 1} of {inner.PageCount}", CultureInfo.CurrentUICulture,
                FlowDirection.LeftToRight, face, 9, Brushes.Gray, dpi);
            dc.DrawText(footer, new Point(
                PageSize.Width - margin.Right - footer.Width,
                PageSize.Height - margin.Bottom / 2));
        }
        container.Children.Add(chrome);

        return new DocumentPage(container, PageSize,
                                page.BleedBox, page.ContentBox);
    }

    public override bool IsPageCountValid => inner.IsPageCountValid;
    public override int PageCount => inner.PageCount;
    public override IDocumentPaginatorSource Source => inner.Source;

    public override Size PageSize
    {
        get => inner.PageSize;
        set => inner.PageSize = value;
    }
}

To use it, replace the last line of PrintDocument above with dialog.PrintDocument(new HeaderFooterPaginator(source.DocumentPaginator, description, new Thickness(48)), description);

inner.PageCount is only accurate once pagination has completed, because the FlowDocument works out page breaks lazily. Until then the footer can print too low a total. Call inner.ComputePageCount() first, or check IsPageCountValid.

Print preview

Users want to see a report before they spend paper on it. WPF's printing pipeline is built on XPS, Microsoft's fixed-layout document format (similar in spirit to PDF), so the easiest preview writes the pages to an XPS file and shows that file in a DocumentViewer: the same pages that printing would produce.

The method writes to a temporary file, opens a modal window with the viewer, and deletes the file afterwards. Notice that the delete comes after the using block: the viewer reads from the file while the window is open, and the file can only be deleted once the block has closed the XPS package.

C# 
// Write an XPS document to a temp file and show it in a DocumentViewer.
public static void ShowPreview(DocumentPaginator paginator, Window owner)
{
    string path = Path.Combine(Path.GetTempPath(), $"preview-{Guid.NewGuid():N}.xps");

    using (var xps = new XpsDocument(path, FileAccess.ReadWrite))
    {
        XpsDocument.CreateXpsDocumentWriter(xps).Write(paginator);

        var viewer = new DocumentViewer { Document = xps.GetFixedDocumentSequence() };
        new Window { Content = viewer, Owner = owner, Width = 900, Height = 1100 }
            .ShowDialog();
    }

    File.Delete(path);
}

Requires a reference to ReachFramework and System.Printing, both of which come with UseWPF.

Choosing a reporting approach

Everything so far uses WPF's own document stack. For many real reports a library does the job better. A FixedDocument, mentioned below, is the opposite of a FlowDocument: every element has an exact position on an exact page, and nothing reflows.

NeedApproach
Print what's on screenPrintDialog.PrintVisual
Multi-page documents from dataFlowDocument built in code + a wrapping paginator
Pixel-exact layout (invoices, labels)FixedDocument, or generate a PDF with QuestPDF
Users design their own reportsA commercial designer, or export to Excel with ClosedXML
PDF outputQuestPDF: fluent, cross-platform, no XPS round-trip. The XPS-to-PDF path on Windows is lossy and awkward.

Silent printing and printer selection DEEPER

A nightly job that prints delivery notes to a named printer cannot stop to show a dialog. It has to find that printer by itself (the code below looks for one whose name contains "Zebra") and send the job straight to it.

The code asks the local print server for its queues, both local printers and connected network printers, picks the first whose name contains "Zebra" (falling back to the default printer), copies that printer's default ticket, adjusts it, and writes the pages directly with an XpsDocumentWriter. Here paginator is any paginator from the sections above. A ticket is a request: to see what the printer will actually accept, pass it through queue.MergeAndValidatePrintTicket.

C# 
using var server = new LocalPrintServer();

PrintQueue queue = server.GetPrintQueues(new[] { EnumeratedPrintQueueTypes.Local, EnumeratedPrintQueueTypes.Connections })
    .FirstOrDefault(q => q.FullName.Contains("Zebra", StringComparison.OrdinalIgnoreCase))
    ?? server.DefaultPrintQueue;

var ticket = queue.DefaultPrintTicket.Clone();
ticket.PageOrientation = PageOrientation.Landscape;
ticket.CopyCount = 2;
ticket.PageMediaSize = new PageMediaSize(PageMediaSizeName.ISOA4);

var writer = PrintQueue.CreateXpsDocumentWriter(queue);
writer.Write(paginator, ticket);        // no dialog
RECAP
  • PrintVisual prints one element as one page, and your code scales it to fit that page first.
  • For anything longer than a page, print a FlowDocument through its paginator, after sizing it to the page.
  • Headers, footers and page numbers come from wrapping the paginator and drawing on top of each page.
  • A preview is an XPS file shown in a DocumentViewer.
  • For invoices, labels and PDFs, a library such as QuestPDF is usually the better tool.
