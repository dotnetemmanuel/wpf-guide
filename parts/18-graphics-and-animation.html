Graphics and animation

Three levels of drawing

LevelWhatCost
ShapeRectangle, Ellipse, Path, Line. Full FrameworkElements: layout, hit-testing, styling, binding.Highest. Fine for tens, painful for thousands.
DrawingGeometryDrawing, ImageDrawing inside a DrawingBrush or DrawingImage. No layout participation.Much cheaper. Right for icons.
VisualDrawingVisual + RenderOpen(), hosted in a FrameworkElement. Bare metal.Cheapest. Right for charts and canvases with thousands of primitives.
XAML — a Path icon, the sane way to do icons 
<ResourceDictionary>
  <Geometry x:Key="SaveGeometry">
    M3,3 H13 L17,7 V17 H3 Z M6,3 V8 H12 V3 M6,17 V12 H14 V17
  </Geometry>
</ResourceDictionary>

<Path Data="{StaticResource SaveGeometry}"
      Fill="{DynamicResource IconBrush}"
      Stretch="Uniform" Width="16" Height="16" />
C# — DrawingVisual for high element counts 
public sealed class ScatterSurface : FrameworkElement
{
    private readonly VisualCollection _visuals;

    public ScatterSurface() => _visuals = new VisualCollection(this);

    protected override int VisualChildrenCount => _visuals.Count;
    protected override Visual GetVisualChild(int index) => _visuals[index];

    public void Render(IReadOnlyList<Point> points, Brush brush)
    {
        _visuals.Clear();

        var visual = new DrawingVisual();
        using (DrawingContext dc = visual.RenderOpen())
        {
            // One visual, many primitives — far cheaper than one Ellipse each.
            foreach (var p in points)
                dc.DrawEllipse(brush, null, p, 2, 2);
        }
        _visuals.Add(visual);
    }

    protected override HitTestResult? HitTestCore(PointHitTestParameters p)
        => new PointHitTestResult(this, p.HitPoint);
}

Brushes and transforms

XAML 
<!-- Brushes -->
<SolidColorBrush Color="#286983" />
<LinearGradientBrush StartPoint="0,0" EndPoint="1,1">…</LinearGradientBrush>
<RadialGradientBrush GradientOrigin="0.3,0.3" />
<ImageBrush ImageSource="/Assets/texture.png" TileMode="Tile"
            Viewport="0,0,64,64" ViewportUnits="Absolute" />
<VisualBrush Visual="{Binding ElementName=Source}" />   <!-- live mirror of an element -->

<!-- RenderTransform: after layout, does not affect siblings -->
<Image RenderTransformOrigin="0.5,0.5">
  <Image.RenderTransform>
    <TransformGroup>
      <ScaleTransform ScaleX="1.1" ScaleY="1.1" />
      <RotateTransform Angle="3" />
    </TransformGroup>
  </Image.RenderTransform>
</Image>

<!-- LayoutTransform: before layout, siblings move out of the way -->
<TextBlock Text="Axis label">
  <TextBlock.LayoutTransform><RotateTransform Angle="-90" /></TextBlock.LayoutTransform>
</TextBlock>

RenderTransform is what you animate — it is cheap and runs on the composition thread. LayoutTransform triggers a full layout pass and should never be animated.

Animation

WPF's animation system animates dependency properties directly, on the render thread, at the display refresh rate. It is genuinely good and almost nobody uses it enough.

XAML 
<Style TargetType="Border" x:Key="Card">
  <Setter Property="RenderTransform">
    <Setter.Value><TranslateTransform /></Setter.Value>
  </Setter>

  <Style.Triggers>
    <EventTrigger RoutedEvent="Loaded">
      <BeginStoryboard>
        <Storyboard>
          <DoubleAnimation Storyboard.TargetProperty="Opacity"
                           From="0" To="1" Duration="0:0:0.18" />
          <DoubleAnimation Storyboard.TargetProperty="RenderTransform.Y"
                           From="8" To="0" Duration="0:0:0.22">
            <DoubleAnimation.EasingFunction>
              <CubicEase EasingMode="EaseOut" />
            </DoubleAnimation.EasingFunction>
          </DoubleAnimation>
        </Storyboard>
      </BeginStoryboard>
    </EventTrigger>
  </Style.Triggers>
</Style>

Animation types you'll use: DoubleAnimation, ColorAnimation, ThicknessAnimation, PointAnimation, plus the …UsingKeyFrames variants for multi-stop sequences, and ObjectAnimationUsingKeyFrames for discrete values like Visibility.

C# 
// From code, with a completion await
static Task AnimateAsync(UIElement target, DependencyProperty prop, double to, TimeSpan duration)
{
    var tcs = new TaskCompletionSource();
    var anim = new DoubleAnimation(to, new Duration(duration))
    {
        EasingFunction = new QuadraticEase { EasingMode = EasingMode.EaseInOut },
        FillBehavior = FillBehavior.HoldEnd,
    };
    anim.Completed += (_, _) => tcs.TrySetResult();
    target.BeginAnimation(prop, anim);
    return tcs.Task;
}

// Release the animation's hold on the property afterwards:
element.BeginAnimation(UIElement.OpacityProperty, null);
element.Opacity = 1;
GOTCHA

An animation with FillBehavior.HoldEnd (the default) keeps the property pinned at precedence level 2 forever — above any local value you subsequently set. Setting element.Opacity = 1 after a fade-out appears to do nothing. Clear the animation with BeginAnimation(prop, null) first, or use FillBehavior.Stop.

Respecting the user's motion setting

C# 
// Windows "Show animations" setting — honour it.
bool animate = SystemParameters.ClientAreaAnimation
            && RenderCapability.Tier > 0;

if (!animate) { element.Opacity = 1; return; }

RenderCapability.Tier tells you how much is hardware-accelerated: 0 means software rendering (remote desktop, some VMs), 2 means full GPU. Dropping animations at tier 0 makes a remote-desktop session feel dramatically better, which matters if your users are on Citrix or RDP.
