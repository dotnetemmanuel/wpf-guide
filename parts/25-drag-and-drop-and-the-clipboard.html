PART 25

Drag and drop, and the clipboard

The drag source

C# 
private Point _dragStart;

private void OnPreviewMouseLeftButtonDown(object sender, MouseButtonEventArgs e)
    => _dragStart = e.GetPosition(null);

private void OnMouseMove(object sender, MouseEventArgs e)
{
    if (e.LeftButton != MouseButtonState.Pressed) return;

    Vector moved = _dragStart - e.GetPosition(null);
    if (Math.Abs(moved.X) < SystemParameters.MinimumHorizontalDragDistance &&
        Math.Abs(moved.Y) < SystemParameters.MinimumVerticalDragDistance) return;

    if (((DependencyObject)e.OriginalSource) is not DependencyObject src) return;
    var container = TreeSearch.FindAncestor<ListBoxItem>(src);
    if (container?.DataContext is not TaskViewModel task) return;

    var data = new DataObject();
    data.SetData(typeof(TaskViewModel).FullName!, task);   // in-process, rich
    data.SetText(task.Title);                              // for other apps

    // Blocks until the drop completes or is cancelled.
    DragDrop.DoDragDrop(container, data, DragDropEffects.Move | DragDropEffects.Copy);
}

Honouring SystemParameters.MinimumHorizontalDragDistance is not optional polish — without it, every click that wobbles by a pixel starts a drag, and selection becomes impossible.

The drop target

XAML 
<ListBox AllowDrop="True"
         DragOver="OnDragOver"
         DragLeave="OnDragLeave"
         Drop="OnDrop" />
C# 
private const string TaskFormat = "Tasks.ViewModels.TaskViewModel";

private void OnDragOver(object sender, DragEventArgs e)
{
    bool ours  = e.Data.GetDataPresent(TaskFormat);
    bool files = e.Data.GetDataPresent(DataFormats.FileDrop);

    e.Effects = (ours, files) switch
    {
        (true, _) => (e.KeyStates & DragDropKeyStates.ControlKey) != 0
                        ? DragDropEffects.Copy : DragDropEffects.Move,
        (_, true) => DragDropEffects.Copy,
        _          => DragDropEffects.None,
    };
    e.Handled = true;       // required, or the parent decides for you
}

private void OnDrop(object sender, DragEventArgs e)
{
    if (e.Data.GetDataPresent(TaskFormat) &&
        e.Data.GetData(TaskFormat) is TaskViewModel task)
    {
        int index = InsertionIndex((ListBox)sender, e.GetPosition((IInputElement)sender));
        _viewModel.MoveTo(task, index);
    }
    else if (e.Data.GetDataPresent(DataFormats.FileDrop) &&
             e.Data.GetData(DataFormats.FileDrop) is string[] paths)
    {
        _viewModel.ImportCommand.Execute(paths);
    }
    e.Handled = true;
}
GOTCHA

Setting e.Effects without e.Handled = true lets an ancestor overwrite it, and you get the "no entry" cursor with no explanation. Also: DragDrop.DoDragDrop runs a nested message loop, so code after it does not execute until the drop finishes, and await inside a drag handler behaves unintuitively. Do the work in Drop, not around DoDragDrop.

An insertion indicator

C# 
private static int InsertionIndex(ListBox list, Point position)
{
    for (int i = 0; i < list.Items.Count; i++)
    {
        if (list.ItemContainerGenerator.ContainerFromIndex(i) is not FrameworkElement c)
            continue;
        Point topLeft = c.TranslatePoint(new Point(0, 0), list);
        if (position.Y < topLeft.Y + c.ActualHeight / 2) return i;
    }
    return list.Items.Count;
}

Draw the line itself with an adorner (Part 24) added on DragOver and removed on DragLeave and Drop. Remember that DragLeave fires when the pointer crosses into a child element too, so debounce it or check e.GetPosition against the bounds.

The clipboard, and what .NET 9 changed

SINCE .NET 9 / .NET 10

.NET 9 removed the BinaryFormatter implementation. WPF used it internally for clipboard and drag-drop of arbitrary objects, so Clipboard.SetData(format, someCustomObject) with a non-primitive type now throws PlatformNotSupportedException unless the type is in WPF's known-safe set. .NET 10 goes further: it unifies the WPF and WinForms clipboard implementations, obsoletes the methods that depended on binary serialisation, and adds JSON-based alternatives. If you are on .NET 9, serialise custom payloads yourself; on .NET 10 you can use the new typed/JSON methods.

C# — portable across .NET 9 and 10 
public static class TaskClipboard
{
    private const string Format = "Tasks.TaskPayload.v1";

    public static void Copy(IReadOnlyList<TaskViewModel> tasks)
    {
        var payload = JsonSerializer.Serialize(tasks.Select(t => t.ToDto()));

        var data = new DataObject();
        data.SetData(Format, payload);                            // a string: always safe
        data.SetText(string.Join(Environment.NewLine,
                     tasks.Select(t => t.Title)));                // for Notepad, Excel…
        data.SetData(DataFormats.CommaSeparatedValue, ToCsv(tasks));

        Clipboard.SetDataObject(data, copy: true);   // copy:true survives app exit
    }

    public static IReadOnlyList<TaskDto> Paste()
    {
        if (!Clipboard.ContainsData(Format)) return [];
        if (Clipboard.GetData(Format) is not string json) return [];
        return JsonSerializer.Deserialize<List<TaskDto>>(json) ?? [];
    }
}

The rule that survives every framework version: put a string on the clipboard, not an object graph. JSON in a private format name, plus text and CSV fallbacks for other applications, works on every .NET and does not depend on the receiving process having your types loaded.

C# — images and files 
Clipboard.SetImage(bitmapSource);
BitmapSource? pasted = Clipboard.ContainsImage() ? Clipboard.GetImage() : null;

var files = new StringCollection();
files.Add(@"C:\reports\q3.pdf");
Clipboard.SetFileDropList(files);
GOTCHA

The clipboard is a shared OS resource and another process can hold it open. Clipboard.SetDataObject throws COMException (CLIPBRD_E_CANT_OPEN) intermittently, especially with remote-desktop clipboard redirection running. Always wrap clipboard access in a retry with a short delay, or use the SetDataObject(data, copy, retryTimes, retryDelay) overload.
