PART 24

Popups, menus, tooltips and adorners

Popup: the primitive under everything floating

Popup creates a separate top-level HWND. That is why it can extend past the window edge, and also why it does not inherit DataContext automatically in some placements, ignores window clipping, and stays put when the window moves unless you tell it not to.

XAML 
<ToggleButton x:Name="Toggle" Content="Filters" />

<Popup IsOpen="{Binding IsChecked, ElementName=Toggle, Mode=TwoWay}"
       PlacementTarget="{Binding ElementName=Toggle}"
       Placement="Bottom"
       HorizontalOffset="0" VerticalOffset="4"
       StaysOpen="False"
       AllowsTransparency="True"
       PopupAnimation="Fade"
       Focusable="False">
  <Border Background="{DynamicResource SurfaceBrush}"
          BorderBrush="{DynamicResource BorderBrush}" BorderThickness="1"
          CornerRadius="6" Padding="12"
          Effect="{StaticResource PopupShadow}">
    <StackPanel>
      <CheckBox Content="Only open" IsChecked="{Binding OnlyOpen}" />
      <CheckBox Content="Assigned to me" IsChecked="{Binding Mine}" />
    </StackPanel>
  </Border>
</Popup>
PropertyWhy it matters
StaysOpen="False"Closes on an outside click. Without it the popup is sticky and users hate it.
AllowsTransparency="True"Required for rounded corners, shadows, or any non-rectangular shape.
PlacementBottom, Right, Mouse, Relative, Custom. Custom takes a CustomPopupPlacementCallback for flip-and-fit logic.
Focusable="False"Keeps keyboard focus on the opener, which is usually what a filter or picker flyout wants.
GOTCHA

A Popup is not a visual child of the element you declared it under, so it inherits DataContext through the logical tree only. If your bindings inside a popup resolve to nothing, set the DataContext explicitly: DataContext="{Binding PlacementTarget.DataContext, RelativeSource={RelativeSource Self}}". Popups also do not move with the window by default — handle LocationChanged and toggle IsOpen, or set Placement="Relative" with a target.

Context menus

XAML 
<ListBox ItemsSource="{Binding Items}">
  <ListBox.ItemContainerStyle>
    <Style TargetType="ListBoxItem">
      <Setter Property="ContextMenu">
        <Setter.Value>
          <ContextMenu>
            <MenuItem Header="_Open"
                      Command="{Binding PlacementTarget.DataContext.OpenCommand,
                                        RelativeSource={RelativeSource AncestorType=ContextMenu}}"
                      CommandParameter="{Binding}" />
            <Separator />
            <MenuItem Header="_Delete"
                      Command="{Binding PlacementTarget.DataContext.DeleteCommand,
                                        RelativeSource={RelativeSource AncestorType=ContextMenu}}"
                      CommandParameter="{Binding}"
                      InputGestureText="Del" />
          </ContextMenu>
        </Setter.Value>
      </Setter>
    </Style>
  </ListBox.ItemContainerStyle>
</ListBox>

The PlacementTarget hop is the standard escape from a context menu's separate visual tree. InputGestureText is display-only — it prints the shortcut in the menu but does not bind it; you still need an InputBinding.

Menus driven by data

XAML 
<Menu ItemsSource="{Binding MenuItems}">
  <Menu.ItemContainerStyle>
    <Style TargetType="MenuItem">
      <Setter Property="Header"           Value="{Binding Header}" />
      <Setter Property="ItemsSource"      Value="{Binding Children}" />
      <Setter Property="Command"          Value="{Binding Command}" />
      <Setter Property="CommandParameter" Value="{Binding Parameter}" />
      <Setter Property="IsCheckable"      Value="{Binding IsCheckable}" />
      <Setter Property="IsChecked"        Value="{Binding IsChecked, Mode=TwoWay}" />
      <Style.Triggers>
        <DataTrigger Binding="{Binding IsSeparator}" Value="True">
          <Setter Property="Template">
            <Setter.Value>
              <ControlTemplate><Separator /></ControlTemplate>
            </Setter.Value>
          </Setter>
        </DataTrigger>
      </Style.Triggers>
    </Style>
  </Menu.ItemContainerStyle>
</Menu>

Using ItemContainerStyle rather than ItemTemplate is deliberate here: a MenuItem must be the container for submenus and keyboard navigation to work. Templating the content instead produces a menu item containing a menu item, which behaves oddly.

Tooltips

XAML 
<Button Content="Export"
        ToolTipService.InitialShowDelay="400"
        ToolTipService.ShowDuration="20000"
        ToolTipService.BetweenShowDelay="0"
        ToolTipService.ShowOnDisabled="True"
        ToolTipService.Placement="Bottom">
  <Button.ToolTip>
    <ToolTip>
      <StackPanel MaxWidth="260">
        <TextBlock Text="Export to CSV" FontWeight="SemiBold" />
        <TextBlock TextWrapping="Wrap" Opacity=".8"
                   Text="Writes the current filtered view, not the whole table." />
      </StackPanel>
    </ToolTip>
  </Button.ToolTip>
</Button>

ShowOnDisabled="True" is the useful one: a disabled button that explains why it's disabled is worth a dozen support tickets.

Adorners

An adorner is a visual drawn in a separate layer on top of its adorned element. It does not participate in layout, so it can overflow without changing anything. Validation error visuals, drag ghosts, resize handles and spell-check squiggles are all adorners.

C# 
public sealed class BadgeAdorner : Adorner
{
    private readonly string _text;
    private readonly Brush _fill = Brushes.Firebrick;
    private readonly Typeface _face = new("Segoe UI");

    public BadgeAdorner(UIElement adorned, string text) : base(adorned)
    {
        _text = text;
        IsHitTestVisible = false;    // let clicks through to the control underneath
    }

    protected override void OnRender(DrawingContext dc)
    {
        var size = AdornedElement.RenderSize;

        var text = new FormattedText(_text, CultureInfo.CurrentUICulture,
            FlowDirection.LeftToRight, _face, 10, Brushes.White,
            VisualTreeHelper.GetDpi(this).PixelsPerDip);

        double r = Math.Max(8, text.Width / 2 + 6);
        var centre = new Point(size.Width - 2, 2);

        dc.DrawEllipse(_fill, null, centre, r, 8);
        dc.DrawText(text, new Point(centre.X - text.Width / 2, centre.Y - text.Height / 2));
    }
}
C# — attaching and removing 
public static void ShowBadge(UIElement element, string text)
{
    var layer = AdornerLayer.GetAdornerLayer(element);
    if (layer is null) return;                       // no AdornerDecorator in the tree

    foreach (var existing in layer.GetAdorners(element)?.OfType<BadgeAdorner>() ?? [])
        layer.Remove(existing);

    layer.Add(new BadgeAdorner(element, text));
}
GOTCHA

AdornerLayer.GetAdornerLayer returns null when there is no AdornerDecorator above the element. A Window's default template has one; Popup, ToolTip, ContextMenu and custom window templates often do not. If adorners vanish inside a flyout, wrap its content in <AdornerDecorator>. Adorners also do not clip to the adorned element and are rendered above everything in that layer — including content you'd expect to be on top.
