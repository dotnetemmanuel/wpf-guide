PART 09

Styles and triggers

A style is a named bag of property setters plus conditional overrides. It is CSS with type safety and without the cascade.

Builds on Part 5, dependency properties (value precedence) and Part 8, resources.

IN PLAIN TERMS

A style is a checklist you hand to a control: padding 12,6, minimum width 88, this font. A trigger is a line on that checklist with a condition: while the mouse is over you, use this background instead. When the condition stops being true, the control goes back to what the checklist said, and you write no clean-up code. Unlike CSS, nothing combines checklists for you: a control takes one style of yours, on top of the theme's built-in one, and your styles build on each other only when you say so.

Keyed and implicit styles

Twenty buttons that need the same padding and font would otherwise repeat the same attributes twenty times, and a redesign means editing every one. A style collects those values in one place. Each value is a setter: a property name and the value to give it. TargetType says which kind of control the style is for.

A style can reach controls in two ways. An implicit style has no key and applies to every control of its target type in scope. A keyed style has an x:Key and applies only to controls that ask for it:

XAML 
<!-- Implicit: applies to every Button in scope, no opt-in -->
<Style TargetType="{x:Type Button}">
  <Setter Property="Padding"    Value="12,6" />
  <Setter Property="MinWidth"   Value="88" />
  <Setter Property="FontFamily" Value="{StaticResource UiFont}" />
</Style>

<!-- Keyed: opt-in by key -->
<Style x:Key="PrimaryButton" TargetType="Button"
       BasedOn="{StaticResource {x:Type Button}}">
  <Setter Property="Background" Value="{StaticResource AccentBrush}" />
  <Setter Property="Foreground" Value="White" />
  <Setter Property="FontWeight" Value="SemiBold" />
</Style>

<Button Style="{StaticResource PrimaryButton}" Content="Save" />

BasedOn="{StaticResource {x:Type Button}}" is the idiom for "inherit from the implicit style": an implicit style is stored under its target type as the key, so this finds it and extends it. Without it, a keyed style silently replaces the implicit one instead of extending it, and the button loses the padding and font you set for every button. The theme's own style still applies underneath, so the button keeps its default look. Its default look is lost only when a style replaces Template (your template is drawn instead) or sets OverridesDefaultStyle to True (nothing is drawn at all).

IN PLAIN TERMS

BasedOn is a recipe that says "the house recipe, plus chilli". Leave it out and you have written a new recipe from scratch that happens to include chilli, so the house seasoning is gone. The restaurant's standard plating, which is the theme style, comes with the dish either way.

GOTCHA

Implicit styles do not apply to derived types. A Style TargetType="ToggleButton" will not touch a CheckBox, even though CheckBox derives from ToggleButton, and a Style TargetType="Button" will not touch your own class derived from Button. There is no wildcard. You write one style per concrete type, usually with BasedOn chaining to a shared base.

Trigger types

A button should change colour on hover, fade when disabled, and show an asterisk when there are unsaved changes. Doing that from event handlers means writing the change and its undo for every case. A trigger is a condition plus setters that apply only while the condition holds. EventTrigger is the exception: it has no setters, and instead starts an animation when an event occurs.

The style below shows all five kinds in one place, and the comments say what each one watches. The difference that matters most: a Trigger watches a property of the element itself, while a DataTrigger watches a binding, usually a view-model property. Animations, which EventTrigger starts, are covered in Part 18.

XAML 
<Style TargetType="Button" x:Key="PrimaryButton">
  <Setter Property="Background" Value="{StaticResource AccentBrush}" />

  <Style.Triggers>

    <!-- Property trigger: one dependency property on THIS element -->
    <Trigger Property="IsMouseOver" Value="True">
      <Setter Property="Background" Value="{StaticResource AccentHoverBrush}" />
    </Trigger>

    <Trigger Property="IsEnabled" Value="False">
      <Setter Property="Opacity" Value="0.45" />
    </Trigger>

    <!-- MultiTrigger: all conditions must hold -->
    <MultiTrigger>
      <MultiTrigger.Conditions>
        <Condition Property="IsMouseOver" Value="True" />
        <Condition Property="IsPressed"   Value="True" />
      </MultiTrigger.Conditions>
      <Setter Property="RenderTransform">
        <Setter.Value><ScaleTransform ScaleX="0.98" ScaleY="0.98" /></Setter.Value>
      </Setter>
    </MultiTrigger>

    <!-- DataTrigger: any BINDING, so any view-model property -->
    <DataTrigger Binding="{Binding IsDirty}" Value="True">
      <Setter Property="Content" Value="Save *" />
    </DataTrigger>

    <!-- MultiDataTrigger: several bindings -->
    <MultiDataTrigger>
      <MultiDataTrigger.Conditions>
        <Condition Binding="{Binding IsDirty}"    Value="True" />
        <Condition Binding="{Binding IsReadOnly}" Value="False" />
      </MultiDataTrigger.Conditions>
      <Setter Property="IsDefault" Value="True" />
    </MultiDataTrigger>

    <!-- EventTrigger: starts a storyboard, cannot set properties -->
    <EventTrigger RoutedEvent="Button.Click">
      <BeginStoryboard>
        <Storyboard>
          <DoubleAnimation Storyboard.TargetProperty="Opacity"
                           From="1" To="0.6" Duration="0:0:0.08" AutoReverse="True" />
        </Storyboard>
      </BeginStoryboard>
    </EventTrigger>

  </Style.Triggers>
</Style>

Read that figure slowly, because three triggers can fail without an error. The asterisk never appears if the button sets its own Content, because a local value outranks a style trigger (Part 5). The hover colour never appears because the default template's own hover trigger paints the border inside the template directly, so the Background your trigger changes is not what you see; Part 10 shows how replacing the template puts you in charge of that border. And after the first click, the Click animation holds Opacity at 1; an animation outranks every trigger, so the disabled fade stops working.

Triggers are declarative and reversible. When the condition stops holding, the previous value comes back automatically: you never write the "undo". That is the reason to prefer a trigger over an event handler that sets a property.

EventSetter DEEPER

Sometimes every control a style touches needs the same handler, such as a double-click on every row of a list. EventSetter is the one way to attach a handler from a style. It only works in a Style, not a ControlTemplate, and the handler must live in code-behind:

XAML 
<Style TargetType="ListBoxItem">
  <EventSetter Event="MouseDoubleClick" Handler="OnItemDoubleClick" />
</Style>

Conditional styling without triggers

Two alternatives worth knowing, because triggers get verbose. Option A uses one DataTemplate per type (Part 10). Option B uses a value converter, a small class that turns a bound value into another value, here a severity into a brush (Part 11).

XAML 
<!-- A. Style selector via DataTemplate DataType: different type, different look -->
<DataTemplate DataType="{x:Type vm:ErrorMessage}">   ... </DataTemplate>
<DataTemplate DataType="{x:Type vm:InfoMessage}">    ... </DataTemplate>

<!-- B. A converter that maps a value to a brush, for many-valued cases -->
<TextBlock Foreground="{Binding Severity, Converter={StaticResource SeverityToBrush}}" />

Rule: two states, use a trigger. Many states driven by an enum, use a converter. Genuinely different shapes of content, use a DataTemplate per type.

RECAP
  • A style is a reusable set of property values, and an implicit style with no key applies to every control of exactly its target type in scope.
  • Use BasedOn to extend a style instead of replacing it.
  • Implicit styles never apply to derived types, so each concrete type needs its own style.
  • Triggers apply setters while a condition holds and undo them automatically when it stops.
  • A value set directly on the element beats every style setter and trigger.
  • Two states call for a trigger, many enum values for a converter, and different shapes for a DataTemplate per type.
